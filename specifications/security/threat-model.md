## Authority, assets and assumptions

Sources read: [architecture security](../architecture.md#security), [product requirements](../product.md#requirements), [Strands ADR](../decisions/0001-strands-agent-sdk.md), and bd show scaleway_ai_vscode-jgh.1.4. Historical planning-only notes do not confer broader authority; current request permits these documents only. [Authorization policy](authorization-policy.md) defines gates; [test cases](security-test-cases.md) specifies future executable assertions. ../../evidence/security/threat-model-checks.json mirrors traceability; all checks are **not_run**.

Protect credentials, connection/organization/project/region/destination identity, workspace prompts/documents, tool/OS authority, portable specs, shared budget reservations, revoke epochs, effect ledger, inspector/evaluation evidence and external sessions. Confidentiality, least privilege and truthful effects take priority over availability. Attackers include malicious workspace/model/tool content, compromised MCP/cloud/dependency, hostile browser/local process and accidental scope/race failures. Compromised host/same-user malware can exceed in-process policy defenses: require OS isolation, pinned dependencies and organizational controls, not a claim of immunity.

## Trust boundaries

| Boundary | Allowed authority/flow | Forbidden trust inference |
|---|---|---|
| Host ↔ webview | Host owns SecretStorage/commands/clients; validated UI intent and minimized events. | No secrets or rendered-content approvals; CSP/nonce is not authorization. |
| Workspace ↔ host/runtime | Trust plus explicit immutable execution/data mandates. | Opening/trusting workspace does not grant launch, installs, shell or data upload. |
| Host ↔ local HTTP runtime | Loopback-bound authenticated per-instance capability and immutable run identity. | No wildcard bind/CORS, tokenless browser call or secret in webview. |
| Runtime ↔ Strands | SDK owns loop; verified wrapper/adapters gate every model/tool/nested/parallel/retry pre-effect path. | SDK choice/source inspection/post-tool trace is not hook verification. |
| Runtime ↔ MCP/OS | Approved server/config/tool schema/effects/env/files/network. | Server output/descriptions cannot expand authority; approved MCP may still be malicious. |
| Host/runtime ↔ model cloud | Exact approved inference destination, purpose credential, data and budget. | Model text is untrusted; no control-plane auth forwarding or arbitrary endpoint/fallback. |
| Host ↔ control plane | Independent read versus resource-write approvals and IAM scope. | GET discovery/create local agent is not deploy/EULA/delete/registry approval. |
| Runtime ↔ session store/trace sink | Explicit scoped authenticated adapter and minimized validated content/retention. | No persisted secrets/authority, cross-tenant IDs, unsolicited telemetry or memory-as-durability. |

## Review blockers and evidence limitations

- Pin exact Strands/Python/model-client/dependency release and prove actual pre-effect interception across sequential/parallel/nested/MCP/model/retry/error paths before enabling effectful runtime. If unsupported, disable effects and escalate; no silent SDK switch or second orchestration loop. **No Strands hook is verified here.**
- HTTP schemas, auth/IAM, TLS/CA/private routing, provider usage, cancellation, pricing, idempotency and lookup semantics remain unverified live contracts. Synthetic checks cannot prove endpoint availability or provider safety.
- Atomic multi-worker accounting, revocation dispatch barrier, durable crash ledger and external session store require implementation/integration evidence. Unknown effect/usage is blocked, not success/free usage.
- Any untreated critical/high finding blocks release unless the authorized reviewer records explicit scoped residual-risk acceptance, evidence, compensating controls and owner. Documentation completeness is not such acceptance.
- Future evidence must label fixture/live provenance, exact commands and version/commit/schema hashes, redacted assertion outcomes and artifact paths. Parent JSON parsing can validate document consistency only.
